# Кандидатогенерация для поиска услуг Авито

Решение для отбора 50 объявлений по поисковому запросу. Основной код и эксперименты находятся в [solution.ipynb](solution.ipynb), поисковые классы — в `src/retrieval.py`.

## Данные и признаки

Использованы три файла из задания:

- `train.parquet` — 497 673 пары «запрос — выбранное объявление». Это источник положительных примеров для обучения и статистики взаимодействий.
- `benchmark_items.parquet` — 189 212 объявлений, из которых формируется итоговая выдача.
- `benchmark_queries.parquet` — 2 452 запроса без разметки.

Признаки использованы следующим образом:

| Признаки | Зачем нужны |
|---|---|
| Текст запроса, заголовок и описание объявления | Найти совпадения по словам и смыслу |
| Текстовые фильтры запроса и параметры объявления | Уточнить требуемый вид услуги |
| Локации запроса и объявления, координаты | Учитывать город и расстояние до исполнителя |
| Подкатегория объявления | Оценить, какие подкатегории выбирали по похожим запросам |
| Рейтинг, число отзывов и цена | Помочь выбрать между объявлениями с похожим содержанием |
| Флаги доступности телефона, сообщений и поиска с доставкой | Учесть дополнительные условия взаимодействия |

Из train также рассчитаны популярность объявлений и частоты переходов из локации поиска в города исполнителей. География учитывается мягко: объявление из другого города не исключается автоматически.

`search_category` почти постоянна, поэтому отдельным признаком модели не используется. Идентификаторы запросов и объявлений не являются обучающими признаками.

## Алгоритм

Сначала несколько методов независимо находят кандидатов:

1. **BM25** по заголовку, описанию и параметрам услуги. Текст приводится к нижнему регистру, `ё` заменяется на `е`, применяется русский стемминг Snowball.
2. **Символьный TF-IDF** по заголовку — дополнительный поиск по частям слов, полезный для словоформ и небольших опечаток.
3. **Семантический поиск** с открытой моделью `intfloat/multilingual-e5-small`. Он позволяет находить объявления без буквального совпадения слов. Веса модели не дообучались.
4. **Поиск по истории похожих запросов** — перенос статистики выбранных объявлений и подкатегорий из train.

Используются как глобальные результаты, так и результаты с учётом географии. Пулы объединяются, повторы удаляются. Затем **CatBoost** оценивает кандидатов по поисковым, географическим и дополнительным признакам и оставляет 50 объявлений.

Поиск по эмбеддингам точный, по всему корпусу. HNSW и EASE в этом решении не использовались.

## Проверка качества

В train нет `query_id`, поэтому локальный запрос определяется комбинацией пяти полей `search_*`. Выбранные объявления внутри группы объединяются без повторов.

Разбиение фиксировано по хешу нормализованного текста запроса. Один текст не попадает одновременно в историю и отложенные части, даже если встречается в разных городах:

- 70% хеш-корзин используются для истории взаимодействий;
- из остальных выбраны 5 000 запросов для обучения отбора, 1 500 для настройки и 2 000 для окончательной проверки.

Для локальных экспериментов к корпусу бенчмарка добавлены релевантные объявления отложенных запросов. Получился индекс из 200 270 объявлений. При формировании итогового CSV разрешены только исходные объявления бенчмарка.

Правильные ответы не добавляются в найденный пул принудительно. Потерянные объявления остаются в знаменателе Recall@50. Для обучения CatBoost отрицательные примеры берутся из поисковой выдачи, а не случайно из всего корпуса.

Результаты на выборке для настройки (dev). Базовый BM25 использует сумму оценок по заголовку и описанию с весами 1 и 0.4:

| Вариант | Recall@50 |
|---|---:|
| BM25 по заголовку и описанию | 0.2662 |
| Текстовый поиск с расстоянием | 0.8152 |
| Текстовый поиск, история локаций и CatBoost | 0.9061 |
| Гибрид с E5, историей локаций и CatBoost | **0.9565** |

По этой выборке выбрана модель с **400 деревьями**. Затем проведена отдельная окончательная проверка на 2 000 запросов: **Recall@50 = 0.9409**. После неё модель не менялась.

Эти метрики рассчитаны на отложенных данных из train. Разметка бенчмарка недоступна. Его запросы в среднем длиннее запросов локальной dev-выборки: 3.20 против 2.34 слова; фильтры встречаются реже: в 36.9% против 67.4% запросов.

Большинство объявлений бенчмарка не встречается в train. Поэтому отдельно проверены 968 dev-запросов, у которых все выбранные объявления отсутствуют в истории взаимодействий: **Recall@50 = 0.9498**.

## Анализ ошибок

| Найденная проблема | Что сделано |
|---|---|
| Конкретная услуга скрыта за общим заголовком: например, «увеличение губ» → «Косметолог» | Добавлены поиск по описанию и семантические кандидаты E5 |
| Пользователь выбирает исполнителя из другого города | Сохранены глобальные кандидаты и добавлена история переходов между локациями |
| У объявления нет истории взаимодействий | Нулевая популярность не исключает его; используются текст, эмбеддинги и характеристики объявления |
| Более длительное обучение ухудшает качество на отложенных запросах | Число деревьев выбирается по dev Recall@50, а не по ошибке обучения |

Остаётся ограничение разметки: отсутствие выбора не означает, что объявление не подходит по смыслу. Часть отрицательных обучающих примеров может быть релевантной.

## Воспроизведение

1. Создайте окружение Python **3.14** и установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

2. Положите три исходных Parquet-файла в папку `data/`.
3. Скачайте `reproduction.zip` из [релиза v1.0.0](https://github.com/NikSila/avito-retrieval-solution/releases/tag/v1.0.0) в корень проекта.
4. Откройте `solution.ipynb` из корня проекта и выполните **Run All**.

Архив содержит обученную модель CatBoost и сохранённые эмбеддинги. Ноутбук заново строит текстовые индексы, находит кандидатов, вычисляет признаки и сохраняет `answer.csv`. Обращения к внешним API при расчёте не нужны.

Последняя ячейка проверяет формат, идентификаторы и SHA-256 отправленного файла.

Для повторения обучения и оценки установите `RUN_EXPERIMENTS = True`. По умолчанию используется сохранённая модель. Желательно 16 ГБ оперативной памяти.

## Открытые инструменты

Использованы NumPy, pandas, PyArrow, SciPy, scikit-learn, Snowball, CatBoost и [multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small).

Версия E5 и код расчёта эмбеддингов приведены в ноутбуке. PyTorch и Transformers нужны только для отдельного пересчёта векторов; обычный запуск использует сохранённые векторы.
